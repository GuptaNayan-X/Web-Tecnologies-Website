01. Client-Side Scripting with JavaScript

JavaScript runs in the browser and responds to user actions. It can calculate values, choose what happens next, update the current page, validate entries, change text, reveal tabs, add animations and fetch new data from a server.

HTML gives structure, CSS gives presentation, and JavaScript gives behavior. JavaScript is a high-level, dynamic scripting language and one of the core technologies of the web; modern browsers run it.

Fundamental building blocks include variables, values, operators, expressions, conditions, loops, functions, objects, arrays and browser APIs such as document and window.

  • Variables: store information that a program can use later.
  • Conditions: if, else if and else choose a branch based on a true/false expression.
  • Loops: repeat work; for, while and for...of are common forms.
  • Functions: package reusable instructions, may receive parameters, and can return a result.

JavaScript Data Types

A data type describes the kind of value a variable contains and the operations that make sense for it. JavaScript is dynamically typed: a variable can hold values of different types at different times, and a type declaration is not written when creating it. Use typeof to inspect many values while learning or debugging.

Conditions, Operators and Loops

Variables and reassignment

Use const for a binding that will not be reassigned and let when reassignment is needed.

JavaScript
const studentName = "Asha";
let marks = 78;
let isPass = marks >= 40;
console.log(studentName); // Asha
console.log(marks);       // 78
console.log(isPass);      // true
marks = marks + 7;
console.log(marks);       // 85

Conditions and logic

Conditions help a program decide what action to take. Logical operators such as && (AND), || (OR) and ! (NOT) combine or reverse logical checks.

JavaScript
const age = 20;
const feesPaid = true;
if (age >= 18 && feesPaid) {
  console.log("Student can register");
} else if (age >= 18 && !feesPaid) {
  console.log("Please pay the fees");
} else {
  console.log("Student is not eligible");
}
const result = (age >= 18) ? "Adult" : "Minor";
console.log(result); // Adult

Loops

Loops repeat a block of instructions until a condition is met. They are useful when processing lists, printing results or checking multiple items one by one.

JavaScript
const subjects = ["HTML", "CSS", "JavaScript", "PHP"];
for (let i = 0; i < subjects.length; i++) {
  console.log("Subject " + i + ": " + subjects[i]);
}
let total = 0;
for (const subject of subjects) { total += 1; }
console.log("Total subjects = " + total); // 4
let count = 1;
while (count <= 3) {
  console.log("Loop count = " + count);
  count++;
}

Functions and Popup Boxes

Functions are reusable blocks of code. They can accept parameters, return results and reduce repeated instructions, making programs easier to manage.

JavaScript
function calculateTotal(price, quantity) {
  return price * quantity;
}
const bill = calculateTotal(120, 3);
console.log(bill); // 360

function greet(student) {
  return "Welcome, " + student + "!";
}
console.log(greet("Asha")); // Welcome, Asha!

02. JavaScript Objects and the DOM

Objects group related data and behavior. An object can contain properties such as name, rollNo and department, along with methods such as displayInfo(). The Document Object Model (DOM) represents an HTML document as a tree of nodes. JavaScript can find nodes, read or change content, update attributes and classes, and create new elements.

The DOM allows pages to respond without reloading. A login form may check a password field, a shopping cart may update totals after a quantity change, and a dashboard may replace a chart when a user selects a different period.

JavaScript
const learner = {
  name: "Asha",
  unit: 4,
  introduce() {
    return `${this.name} is studying Unit ${this.unit}.`;
  }
};
const message = document.querySelector("#message");
message.textContent = learner.introduce();

03. Forms and Validation

Form validation checks user input before an application accepts or sends it. HTML provides basic constraints; JavaScript can add application-specific checks and feedback. Validation guides users, reduces errors and can stop invalid data before submission.

Typical checks include whether a field is empty, whether a password is long enough, whether an email resembles the expected format, and whether required values are selected. HTML attributes provide built-in rules, while browser validation APIs let developers combine built-in rules with custom logic.

AttributeExampleWhat it checks
required<input required>A value must be entered or selected.
type<input type="email">Uses a suitable input and checks basic formats such as email or URL.
minlength / maxlengthminlength="2" maxlength="40"Sets allowed text length.
min / max / steptype="number" min="1" max="10" step="1"Limits numeric/date values and permitted increments.
patternpattern="[A-Z]{2}[0-9]{4}"Requires text to match a regular-expression pattern.

Validation flow

  1. Collect the values when the user submits the form.
  2. Check basic constraints, such as required fields and valid input types.
  3. Apply extra application-specific rules and explain how to correct errors.
  4. Continue only when values pass; validate them again on the server.

checkValidity() returns true when all constraints pass. reportValidity() asks the browser to display validation feedback. The validity property gives details about validity state, and setCustomValidity(message) can add a custom error. Clear a custom error with setCustomValidity("") when the value becomes valid.

JavaScript
form.addEventListener("submit", (event) => {
  event.preventDefault();
  if (!form.checkValidity()) {
    form.reportValidity();
    message.textContent = "Please correct the highlighted fields.";
    return;
  }
  message.textContent = "Form is ready to submit.";
});

Enter a name and a valid email address, then submit.

Important: client-side validation improves feedback but is not a security boundary. A user can disable JavaScript or send data directly to a server, so the server must validate submitted data too.

04. DHTML: HTML, CSS and JavaScript Together

DHTML stands for Dynamic HTML. It is a descriptive term for using HTML, CSS and JavaScript together to make a page respond to changes and user actions. It is not a separate programming language, browser feature or software package.

  • HTML: supplies elements and meaning, such as headings, cards, forms and buttons.
  • CSS: controls layout, colors, spacing and visual states.
  • JavaScript: listens for events, makes decisions and updates DOM content, attributes or classes.

How a DHTML interaction works

  1. The browser reads HTML and creates a DOM tree.
  2. The browser applies CSS rules to determine appearance.
  3. JavaScript finds the relevant elements and registers an event listener.
  4. When the event occurs, JavaScript updates the DOM; the browser applies changed styles and renders the result.

A common pattern is to use JavaScript to add or remove a CSS class rather than placing visual styling directly in JavaScript.

HTML
<div class="dhtml-card" id="dhtml-card">
  <h4>Interactive course card</h4>
  <p>Press the button to highlight this card.</p>
</div>
<button type="button" id="dhtml-toggle">Toggle highlight</button>
CSS
.dhtml-card { padding: 16px; background: #f1f5f5; }
.dhtml-card.is-active { color: white; background: #087e78; }
JavaScript
const card = document.querySelector("#dhtml-card");
const toggleButton = document.querySelector("#dhtml-toggle");
toggleButton.addEventListener("click", () => {
  card.classList.toggle("is-active");
});

Good practice: keep content in HTML, visual rules in CSS and interaction logic in JavaScript. Use semantic HTML controls such as a real <button> so keyboard users can activate the interaction too.

05. Events and Buttons

An event is something that happens in the browser, such as a click, key press, form submission or page load. An event listener connects an event to a function. Prefer addEventListener() so behavior stays separate from HTML structure and multiple listeners can be attached without mixing logic into inline markup.

The browser creates an event object containing useful information, such as the event type and the element involved. Developers can inspect it to decide how to respond.

06. AJAX and Asynchronous Web Applications

AJAX stands for Asynchronous JavaScript and XML. The name comes from an earlier period when XML was a common response format. Today, AJAX describes sending an HTTP request from JavaScript and updating part of a page with the response without loading a new document. JSON is common, but responses may also be text, HTML, XML or another resource type.

This pattern is useful when only one part of a page needs new information, such as searching a catalog, refreshing messages, checking a username or submitting a form. AJAX is a communication pattern, not a server or database by itself.

Request and response cycle

  1. A user action or another event starts a request to a server URL, often called an endpoint.
  2. The browser sends a request, commonly with GET to retrieve data or POST to send data.
  3. The server returns a response with a status and, when appropriate, a body such as JSON or text.
  4. JavaScript checks the response, reads the body and updates the needed DOM elements.
  5. The rest of the document stays in place; the interface can show loading, success or error feedback along the way.

What asynchronous means

A synchronous operation makes the next step wait for the current one to finish. Network requests can take time, so APIs such as fetch() work asynchronously and return a Promise representing work that will finish later. While network activity is handled, JavaScript can continue responding to events and the page can remain interactive. An async function can use await; this pauses that function until its Promise settles, not the entire browser interface.

Using fetch and handling errors

A successful fetch() call gives JavaScript a response object, but an HTTP status such as 404 or 500 does not normally reject the Promise. Check response.ok before reading the body. response.json() is also asynchronous and can fail if the body is not valid JSON.

JavaScript
async function loadCourses() {
  status.textContent = "Loading courses...";
  try {
    const response = await fetch("/api/courses");
    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }
    const courses = await response.json();
    output.textContent = courses.map(course => course.name).join(", ");
    status.textContent = "Courses loaded.";
  } catch (error) {
    status.textContent = "Could not load courses. Check the connection.";
    console.error(error);
  }
}
loadCourses();

/api/courses is a placeholder endpoint; it must exist and return JSON containing an array of course objects with a name property. The try...catch handles network errors, non-success HTTP statuses explicitly turned into errors, and problems reading or parsing the response body.

Cross-origin requests: a page can usually request resources from its own origin. If an API is hosted on a different origin, the server must allow the page through Cross-Origin Resource Sharing (CORS). Adding mode: "no-cors" is not a general fix because it produces an opaque response that JavaScript cannot read normally.

Demo note: a local AJAX-style demo may simulate a wait and display sample data without contacting a server. A real fetch request requires a working endpoint.

07. Introduction to jQuery

jQuery is a JavaScript library that offers concise APIs for selecting elements, handling events, updating the DOM, effects and AJAX. It was especially valuable when browser differences required extra compatibility work. Modern browsers provide many equivalent capabilities directly, but jQuery remains in existing projects and is useful to recognize when reading or maintaining older websites.

Its main advantage is shorter, chain-based code. The $() function accepts CSS-style selectors; jQuery also provides convenient event, content and class methods.

JavaScript + jQuery
// Include the jQuery library before running this script.
$(function () {
  $("#jquery-button").on("click", function () {
    $("#jquery-message")
      .text("Updated by a jQuery event handler.")
      .toggleClass("is-highlighted");
  });
});

The document-ready callback runs after the document is ready for manipulation. jQuery must be included before its API can run. Learn the JavaScript DOM model first; jQuery becomes easier to understand once the browser object model is familiar.

Unit 4 Recap

  1. JavaScript provides variables, decisions, loops, functions and popup APIs.
  2. Objects group values and methods; the DOM lets scripts inspect and update a document.
  3. Validate forms in the browser for usability, and repeat validation on the server for security.
  4. DHTML describes the combination of HTML, CSS and JavaScript; events connect user actions to code.
  5. AJAX updates page regions asynchronously; JSON is common even though the name says XML.
  6. jQuery is a library for DOM, event, effect and request operations; modern JavaScript has native alternatives.

Must-learn JavaScript topics for first year

  • Variables: let, const
  • Data types: string, number, boolean, array and object
  • Arithmetic, comparison and logical operators
  • Conditions: if, else if, else
  • Loops: for, while, for...of
  • Functions, parameters, return values and reuse
  • Events and addEventListener()
  • DOM selection and manipulation
  • Form validation basics
  • Arrays, objects and debugging with the browser console
  • Simple AJAX / fetch() understanding
  • Basic jQuery recognition and usage
  • Writing small programs and mini-projects

Beginner-friendly summary

JavaScript makes a web page interactive. It stores data in variables, checks conditions, repeats actions with loops, reuses logic with functions, responds to user actions through events and changes page content through the DOM. It can validate forms, fetch data from a server and build dynamic experiences. HTML defines what is on the page, CSS decides how it looks, and JavaScript decides what happens when a user interacts with it.
