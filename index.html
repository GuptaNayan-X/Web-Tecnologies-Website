Introduction to Web Technologies

Web Technologies is the study of how the World Wide Web actually works — the protocols, servers and addressing schemes that move information around, and the markup language, HTML, used to structure what people see in a browser. The Web is a system of interconnected pages reachable through the Internet's TCP/IP infrastructure: a browser (client) requests a resource over HTTP, a server returns it, and standards from the W3C keep every browser and server speaking the same language.

Unit 1

World Wide Web Architecture

Protocols, server architectures, dynamic IP, Web 2.0 & design standards.

What Is the World Wide Web?

The WWW is a system of interconnected pages and information accessed over the Internet, using hyperlinks to navigate between documents in text, image, audio and video formats. It was invented by Tim Berners-Lee at CERN in 1989, and the World Wide Web Consortium (W3C) was founded to keep its standards open. The very first website is still live at http://info.cern.ch/. Today the Web hosts 1.5 billion+ sites in 150+ languages, reaches over 63% of the world's population, and is browsed mostly through Chrome (60%+ share).

Web 1.0 (1990–2000)
Static, read-only, one-way information sharing.
Web 2.0 (2000–2010)
Interactive, social, user-generated content.
Web 3.0 (2010–2020)
Semantic web — machines understand and personalize data.
Web 4.0 (2020–2030)
Intelligent, AI-driven, decentralized "web OS".

Internet vs. World Wide Web

The InternetThe World Wide Web
LayerHardware / network layerApplication / data layer
What it isA globally decentralized network of networks running TCP/IP — routers, fiber, packet switching, IP routingAn information system running on top of the Internet, using hypertext, URIs and HTTP

Key takeaway: the Internet provides the infrastructure (the roads); the WWW provides the service (the traffic on them).

Browsers, Servers & the Client–Server Model

The Web runs on a client–server architecture: the browser requests a resource and the server returns it. A browser is a software interface — Chrome, Opera Mini, Internet Explorer — that renders text/pictures/animation/video, and also handles searching, file transfer and mail.

Web browser
Rendering engine (Blink, Gecko, WebKit) builds the DOM/CSSOM; a JS engine (V8, SpiderMonkey) runs scripts; a network/storage layer handles cache, cookies and TLS.
Web server
Listens on ports 80/443, serves files or routes to an app. Apache uses one process/thread per connection; Nginx/Node.js is async event-driven, handling 10k+ connections efficiently.

HTTP: Request & Response

Request
Line: method + URI + version, e.g. GET /api/data HTTP/1.1 · Headers: Host, User-Agent, Accept · Body: payload for POST/PUT
Response
Status line: version + code, e.g. HTTP/1.1 200 OK · Headers: Content-Type, Set-Cookie, Cache-Control · Body: HTML, CSS or JSON

Request–response lifecycle:

  1. DNS resolution — browser converts the domain to an IP via local cache → recursive resolver → root/TLD → authoritative DNS.
  2. TCP 3-way handshake — client sends SYN, server replies SYN-ACK, client sends ACK, on port 80 or 443.
  3. HTTP transmission — client sends the request; server runs routing/DB logic and returns the response.
  4. Teardown / keep-alive — socket closes, or stays open for further requests.

URI vs. URL

URI is the umbrella term for anything that identifies a resource — a URL identifies by location, a URN identifies by name regardless of location (e.g. urn:isbn:978-0-395-36341-6). A URL is a URI that also tells you how to reach the resource, so it always includes a scheme, e.g. https://www.google.com. Analogy: a URI is like a person's name; a URL is their full home address.

Anatomy of a URL — https://www.itmbu.ac.in:

PartValueMeaning
Schemehttps://Protocol; the "s" means an encrypted SSL/TLS connection
SubdomainwwwConventional label for the main public web server
2nd-level domainitmbuThe organisation's chosen name
TLD.ac.in.ac = academic institution, .in = India ccTLD

Domain Names, Labels & TLDs

Domain names are human-readable stand-ins for hard-to-remember IP addresses, and are parsed right to left (e.g. developer.mozilla.org → TLD → label1 → label2). A label can be 1–63 characters, is case-insensitive, and may only use letters, digits and hyphens (never as the first/last character). The label directly before the TLD is the second-level domain (SLD); a domain isn't limited to 3 labels — informatics.ed.ac.uk is valid, and any base domain can delegate subdomains (support.mozilla.org).

Generic TLDs
.com, .org, .net — no eligibility rules.
Country-code TLDs
.in, .fr, .us — may require local language or hosting.
Restricted TLDs
.gov (government only), .edu / .ac (accredited institutions only).

You never permanently own a domain — you pay a registrar (which uses a registry) for the right to use it for one or more years, renewable ahead of other applicants. Some TLDs skip standard registrars entirely — every .fire domain, for example, is managed directly by Amazon.

IP Addressing: IPv4 vs. IPv6

An IP address is a unique numeric label assigned to every network-connected device, allocated under IANA rules (ranging 0.0.0.0–255.255.255.255 for IPv4).

FeatureIPv4IPv6
Size32-bit128-bit
NotationDecimal dotted — 192.168.5.18Hex colon — 2001:db8::1
Address space~4.3 billion (nearly exhausted)340 undecillion
ConfigurationManual or DHCPSLAAC, DHCPv6 or manual
NATOften requiredEnd-to-end connectivity, no NAT needed
SecurityIPsec optionalIPsec built in
HeaderVariable, 20–60 bytesFixed, 40 bytes
Public
The router's external address facing the ISP/Internet.
Private
Internal LAN address, reused across networks to save IPv4 space (IPv6 equivalent: ULA).
Static
Manually fixed; used for servers, DNS, production systems.
Dynamic
Auto-assigned by DHCP from a pool; changes on reboot/lease expiry.

Reserved addresses: 0.0.0.0 default network · 127.0.0.1 loopback (self-test) · 169.254.0.1–254 link-local (auto-assigned when DHCP fails) · 255.255.255.255 broadcast.

IPv4 Limitations, IPv6 Benefits & Address Classes

IPv4's 32-bit space is nearly exhausted, and it shows in three places: scalability (limited addresses plus wasteful broadcast overhead), routing (complex, variable-length headers and manual/DHCP misconfiguration slow every hop), and security (IPsec isn't built in, and QoS prioritisation for real-time video/voice is weak). IPv6 fixes all three with a 128-bit space, a simplified fixed 40-byte header, built-in IPsec, native QoS, and mobile-friendly design.

Transition strategies: dual stacking (a device runs IPv4 and IPv6 side by side), tunneling (IPv6 packets are wrapped inside IPv4 to cross older networks), and NAT (translates addresses so the two IP versions can talk to each other).

IP vs. MAC Address, and Staying Safe

IP address
Network-layer connection identifier, 4 bytes (IPv4) or 16 bytes (IPv6), assigned by the ISP, usually dynamic, and visible to third parties online.
MAC address
Data-link-layer physical identifier, 6-byte hex, set by the hardware manufacturer, static/permanent, and private — visible only on your own LAN.

An exposed IP can be used for geographic tracking, targeted DDoS attacks, or to falsely implicate you in illegal downloads. Protect it with a VPN, a proxy server, a NAT firewall, ISP-rotated dynamic IPs, or simply by resetting your modem.

Dynamic IP & Dynamic DNS (DDNS)

Problem: standard DNS A-records map a domain to a fixed IP. When a home or small-business server's dynamic IP changes, the domain lookup breaks.

Solution: a lightweight DDNS daemon on the server watches the WAN IP; whenever it changes, the daemon sends an authenticated API request that updates the DNS A-record within seconds, keeping the domain reliably pointed at the server.

Web 2.0 Technologies

AJAX / async
XMLHttpRequest and fetch() fetch data in the background without a full reload — enabling single-page apps.
User-generated content
Shift from static one-way pages to participatory platforms — social networks, wikis, blogs.
RESTful APIs
Lightweight JSON over HTTP REST replaced heavy SOAP/XML, enabling third-party mashups.
SaaS
Apps moved from installed binaries to cloud-hosted browser apps (Docs, Figma, Office 365).

Deploying a Linux Web Server

  1. Install packages — sudo apt update && sudo apt install apache2 nginx on Debian/Ubuntu.
  2. Directory & permissions — document root at /var/www/html, ownership assigned via chown.
  3. Virtual hosts — per-domain config files in sites-available, letting one IP serve multiple domains.
  4. Firewall & SSL — open HTTP/HTTPS ports with ufw; issue certificates via Let's Encrypt / Certbot.

Effective Web Design Principles

Visual hierarchy / F-pattern
Users scan, not read — eye-tracking shows an F-shaped pattern, so put logos, nav and CTAs along the top-left path.
3-click rule
Clear sitemaps and breadcrumbs so any content is reachable within 3 clicks.
Responsive design (RWD)
Fluid layouts across phones/tablets/desktops via media queries, flexbox and grid.
Accessibility (WCAG 2.1)
Minimum 4.5:1 text contrast, image alt text, full keyboard navigation.
Performance
Core Web Vitals (LCP/CLS/FID) improved via image compression, minification, CDNs; 1s loads convert far better than 4s loads.
Cross-browser & security
CSS resets/autoprefixer for engine differences; enforce Content-Security-Policy headers to block XSS and clickjacking.

HTML

Document structure, elements, attributes, formatting, and HTML5.

What Is HTML?

HTML (HyperText Markup Language) is the standard markup language for creating web pages. It describes a page's structure through nested elements that define layout blocks; the browser interprets these tags to render content — it never displays the raw tags themselves.

html
<!DOCTYPE html>
<html>
  <head>
    <title>Page Title</title>
  </head>
  <body>
    <h1>My First Heading</h1>
    <p>My first paragraph.</p>
  </body>
</html>

<!DOCTYPE html> declares an HTML5 document · <html> is the root element · <head> holds metadata · <title> sets the browser tab text · <body> contains everything visible.

Tip: press Ctrl+U (Cmd+Option+U on Mac) to view a page's raw source, or right-click → Inspect to explore live elements and styles in DevTools.

A Brief History of HTML

1989 Tim Berners-Lee invents the Web → 1991 he writes HTML → 1993 Dave Raggett drafts HTML → 1995 HTML 2.0 → 1997 HTML 3.2 (W3C) → 1999 HTML 4.01 → 2000 XHTML 1.0 → 2008–2014 WHATWG drafts culminate in the HTML5 W3C Recommendation (2014) → 2016–2017 HTML 5.1 / 5.2.

Elements, Tags & Nesting

An element = start tag + content + end tag, e.g. <p>My first paragraph.</p>. Empty elements like <br> have no content and no closing tag. Elements nest inside one another, and closing tags must mirror the opening order: <html><body>…</body></html>.

Never skip a closing tag — browsers may auto-correct malformed markup, but relying on that causes unpredictable rendering, style leakage and accessibility bugs. HTML tags are case-insensitive (<P> = <p>), but W3C recommends — and XHTML requires — lowercase.

HTML Attributes

Attributes live only in the start tag, as name="value" pairs, and modify an element's default behaviour.

AttributeUsed onPurpose
href<a>Link destination
src<img>Resource path — absolute (external) or relative (local, more resilient)
width / height<img>Reserves layout space, prevents shift while loading
alt<img>Fallback text for accessibility / broken images
styleany elementInline CSS, e.g. style="background-color:powderblue;"
lang<html>Declares page language, e.g. lang="en-US"
titleany elementHover tooltip / advisory text

Always quote attribute values (mandatory once a value contains a space) and prefer lowercase attribute names. If a value itself contains quotes, alternate styles: title='John "Ace" Smith' or title="John 'Ace' Smith".

Headings, Paragraphs & Whitespace

<h1>–<h6> define six levels of heading importance — use only one <h1> per page, and never use headings just to make text big or bold (search engines use them to index structure; resize with style="font-size:60px;" instead). <p> defines a block-level paragraph; browsers add margin before and after automatically.

Extra spaces and line breaks in your source code collapse to a single space when rendered (the "poem problem") — use <pre> to preserve exact whitespace and line breaks in a monospace font. <hr> inserts a thematic break; <br> forces a line break without starting a new paragraph.

HTML Colors

Colors can use 140+ named keywords or three numeric models:

  • RGB — rgb(red, green, blue), each 0–255, e.g. rgb(255,99,71); RGBA adds an alpha (0–1) for opacity.
  • HEX — #RRGGBB, two hex digits per channel, e.g. #ff6347.
  • HSL — hsl(hue, saturation, lightness): hue 0–360° (0=red, 120=green, 240=blue), saturation 0–100% (0%=gray → 100%=full color), lightness 0–100% (0%=black → 100%=white). HSLA adds an alpha channel.

Try it — live HSL mixer:

hsl(210,70%,55%)

Hyperlinks

html
<a href="https://www.itmbu.ac.in" target="_blank">Visit ITMBU</a>
<a href="https://example.com"><img src="logo.png" alt="Logo"></a>
<a href="mailto:info@itmbu.ac.in">Email us</a>

Images and buttons can be wrapped in an <a> too, and mailto: links open the user's email client. The target attribute controls where the link opens: _self (default, same tab), _blank (new tab), _parent, _top.

Absolute URL — full address to an external resource. Relative URL — a path within the same site (e.g. images/pic.jpg); preferred, since it survives a domain change.

Lists

<ul>
Unordered (bulleted) list of <li> items; type can be disc, circle or square.
<ol>
Ordered (numbered) list of <li> items; type can be 1, A, a, I or i.
<dl>
Description list pairing <dt> (term) with <dd> (description).

Tables

<table> defines the table, <tr> a row, <td> a standard cell, <th> a bold, centered header cell.

html
<table>
  <tr><th>Name</th><th>Marks</th></tr>
  <tr><td>Asha</td><td>92</td></tr>
</table>

Images

html
<img src="img_girl.jpg" alt="Girl with a jacket" width="500" height="600">

<img> is an empty (self-closing) element. src can be absolute or relative; alt is essential for accessibility and shows if the image fails to load; width/height prevent layout shift while loading. Common formats: JPEG, PNG, GIF, SVG, WebP.

Forms & Input

html
<form action="/action_page.php">
  <label for="fname">First name:</label>
  <input type="text" id="fname" name="fname">
  <input type="submit" value="Submit">
</form>

<form> wraps and coordinates all input controls, typically posting to a server via action. <input> is the core control — its behaviour depends on type:

TypeBehaviour
textSingle-line text field
radioPick one option from a group sharing the same name
checkboxPick any number — selections are independent
submitSends the form data to the server
emailHTML5 — validates an @ symbol
dateHTML5 — native calendar picker
colorHTML5 — native color picker
rangeHTML5 — draggable slider

<label for="id"> ties descriptive text to a control by matching its id — screen readers read it aloud, and clicking the label focuses/toggles the control.

HTML5: Semantics, Media & APIs

Semantic elements replace generic <div id="header"> with self-describing tags — <header>, <nav>, <main>, <article>, <section>, <aside>, <footer> — improving SEO and screen-reader navigation.

html
<video width="600" controls>
  <source src="lecture.mp4" type="video/mp4">
</video>

<audio controls>
  <source src="podcast.mp3" type="audio/mpeg">
</audio>

Native <video> / <audio> need no plugins. The Drag & Drop API: add draggable="true" to make any element draggable, then handle JS events like ondragstart and ondragover.

Meta Tags & XHTML

Meta tags live inside <head>, invisible to visitors but critical for machines:

TagPurpose
<meta charset="UTF-8">Character encoding
<meta name="viewport" content="width=device-width, initial-scale=1">Responsive scaling on mobile
<meta name="description" content="...">Summary shown in search results

XHTML is the strict, XML-based version of HTML: tags must be lowercase, every element must be properly closed — including empty ones, e.g. <br /> — and nesting must be perfectly ordered. Unlike HTML5, it won't forgive small mistakes.
