World Wide Web Architecture

Protocols, server architectures, dynamic IP, Web 2.0 & design standards.

What Is the World Wide Web?

The WWW is a system of interconnected pages and information accessed over the Internet, using hyperlinks to navigate between documents in text, image, audio and video formats. It was invented by Tim Berners-Lee at CERN in 1989, and the World Wide Web Consortium (W3C) was founded to keep its standards open. The first website, created at CERN, is preserved at http://info.cern.ch/. The Web has grown into a global information system used by people around the world.

Web 1.0 (often used for the early Web)
A shorthand for mostly static pages and limited user interaction.
Web 2.0 (popularized in the mid-2000s)
A shorthand for interactive services, social platforms and user-generated content.
Web 3.0 (proposed meanings vary)
May refer to the semantic web or, in other discussions, decentralized technologies; there is no single agreed definition.
Web 4.0
An informal and speculative term with no universally agreed definition or timeline.

The InternetThe World Wide Web
LayerHardware / network layerApplication / data layer

Key takeaway: the Internet provides the infrastructure (the roads); the WWW provides the service (the traffic on them).

Browsers, Servers & the Client–Server Model

The Web commonly uses a client–server architecture: a browser requests a resource and a server returns it. A browser renders web documents, runs client-side scripts and handles network communication and user interaction. Mail and file-transfer services may be accessed through web applications, but are not browser-server functions by themselves.

Web browser
Rendering engine (Blink, Gecko, WebKit) builds the DOM/CSSOM; a JS engine (V8, SpiderMonkey) runs scripts; a network/storage layer handles cache, cookies and TLS.
Web server
Accepts HTTP connections, serves files or routes requests to an application. Apache and Nginx support different concurrency models; capacity depends on configuration, workload and available resources.

HTTP: Request & Response

Request
Line: method + URI + version, e.g. GET /api/data HTTP/1.1 · Headers: Host, User-Agent, Accept · Body: payload for POST/PUT
Response
Status line: version + code, e.g. HTTP/1.1 200 OK · Headers: Content-Type, Set-Cookie, Cache-Control · Body: HTML, CSS or JSON

Request–response lifecycle:

  1. DNS resolution — browser converts the domain to an IP via local cache → recursive resolver → root/TLD → authoritative DNS.
  2. Transport connection — HTTP/1.1 and HTTP/2 commonly use TCP (usually port 80 or 443); HTTP/3 uses QUIC over UDP.
  3. HTTP transmission — client sends the request; server runs routing/DB logic and returns the response.
  4. Teardown / keep-alive — socket closes, or stays open for further requests.

URI vs. URL

URI is the umbrella term for anything that identifies a resource — a URL identifies by location, a URN identifies by name regardless of location (e.g. urn:isbn:978-0-395-36341-6). A URL is a URI that also tells you how to reach the resource, so it always includes a scheme, e.g. https://www.google.com. Analogy: a URI is like a person's name; a URL is their full home address.

Anatomy of a URL — https://www.itmbu.ac.in:

Domain Names, Labels & TLDs

Domain names are human-readable stand-ins for hard-to-remember IP addresses, and are parsed right to left (e.g. developer.mozilla.org → TLD → label1 → label2). A label can be 1–63 characters, is case-insensitive, and may only use letters, digits and hyphens (never as the first/last character). The label directly before the TLD is the second-level domain (SLD); a domain isn't limited to 3 labels — informatics.ed.ac.uk is valid, and any base domain can delegate subdomains (support.mozilla.org).

Generic TLDs
.com, .org and .net are broadly open to registration, subject to registry and registrar policies.
Country-code TLDs
.in, .fr, .us — may require local language or hosting.
Restricted TLDs
.gov is for eligible U.S. government entities; .edu is for eligible U.S. postsecondary institutions. Eligibility rules depend on the registry.

You never permanently own a domain — you pay a registrar (which uses a registry) for the right to use it for one or more years, renewable ahead of other applicants. Some TLDs skip standard registrars entirely — every .fire domain, for example, is managed directly by Amazon.

IP Addressing: IPv4 vs. IPv6

An IP address identifies a network interface for communication at the IP layer. IANA coordinates global address allocation through regional Internet registries; networks and administrators assign addresses to interfaces. IPv4 addresses are 32-bit values, from 0.0.0.0 to 255.255.255.255.

IPv4 Limitations, IPv6 Benefits & Address Classes

IPv4's 32-bit address space is limited. IPv6 provides a much larger 128-bit address space, a simplified fixed 40-byte base header, and fields that support traffic classification and prioritization. IPv6 standards include IPsec support, but encryption is not automatic: applications and networks still need to configure appropriate security.

Transition strategies: dual stacking (a device runs IPv4 and IPv6 side by side), tunneling (IPv6 packets are wrapped inside IPv4 to cross older networks), and translation mechanisms such as NAT64 with DNS64 (which let compatible IPv6-only clients reach IPv4 services).

IP vs. MAC Address, and Staying Safe

IP address
Network-layer address, 4 bytes (IPv4) or 16 bytes (IPv6), assigned by a network. A public address is visible to services it communicates with; a private address is normally used within a local network.
MAC address
Link-layer interface address, commonly 48 bits and written in hexadecimal. It may be assigned by a manufacturer or locally configured, and operating systems can randomize it. It is normally used on the local link rather than routed across the Internet.

A public IP address can reveal an approximate network location and ISP, and an exposed service may receive unwanted traffic. An IP address alone does not identify a particular person or prove who performed an action. A VPN or proxy can make a destination see the intermediary's address instead of yours; the intermediary may still see your address. A router firewall can block some unsolicited inbound connections, but does not hide your address from websites you visit. Dynamic addresses can change, but this is not guaranteed by renewing a lease or restarting a modem.

Dynamic IP & Dynamic DNS (DDNS)

Problem: a DNS A record maps a hostname to an IPv4 address. If a server's dynamic address changes and its DNS record is not updated, clients may continue reaching the old address.

Solution: a lightweight DDNS daemon on the server watches the WAN IP; whenever it changes, the daemon sends an authenticated API request that updates the DNS A-record within seconds, keeping the domain reliably pointed at the server.

Web 2.0 Technologies

AJAX / async
XMLHttpRequest and fetch() fetch data in the background without a full reload — enabling single-page apps.
User-generated content
Shift from static one-way pages to participatory platforms — social networks, wikis, blogs.
Web APIs
REST-style APIs and JSON became widely used alongside SOAP/XML services, enabling applications to exchange data and integrate services.
SaaS
Apps moved from installed binaries to cloud-hosted browser apps (Docs, Figma, Office 365).

Deploying a Linux Web Server

  1. Install a web server — on Debian/Ubuntu, run sudo apt update, then choose either sudo apt install apache2 or sudo apt install nginx.
  2. Directory & permissions — document root at /var/www/html, ownership assigned via chown.
  3. Virtual hosts — per-domain config files in sites-available, letting one IP serve multiple domains.
  4. Firewall & SSL — open HTTP/HTTPS ports with ufw; issue certificates via Let's Encrypt / Certbot.

Effective Web Design Principles

Visual hierarchy / F-pattern
Users scan, not read — eye-tracking shows an F-shaped pattern, so put logos, nav and CTAs along the top-left path.
3-click rule
Clear sitemaps and breadcrumbs so any content is reachable within 3 clicks.
Responsive design (RWD)
Fluid layouts across phones/tablets/desktops via media queries, flexbox and grid.
Accessibility (WCAG 2.1)
Minimum 4.5:1 text contrast, image alt text, full keyboard navigation.
Performance
Core Web Vitals (LCP/CLS/FID) improved via image compression, minification, CDNs; 1s loads convert far better than 4s loads.
Cross-browser & security
CSS resets/autoprefixer for engine differences; enforce Content-Security-Policy headers to block XSS and clickjacking.
