World Wide Web Architecture

Protocols, server architectures, dynamic IP, Web 2.0 & design standards.

What Is the World Wide Web?

The WWW is a system of interconnected pages and information accessed over the Internet, using hyperlinks to navigate between documents in text, image, audio and video formats. It was invented by Tim Berners-Lee at CERN in 1989, and the World Wide Web Consortium (W3C) was founded to keep its standards open. The very first website is still live at http://info.cern.ch/. Today the Web hosts 1.5 billion+ sites in 150+ languages, reaches over 63% of the world's population, and is browsed mostly through Chrome (60%+ share).

Web 1.0 (1990–2000)
Static, read-only, one-way information sharing.
Web 2.0 (2000–2010)
Interactive, social, user-generated content.
Web 3.0 (2010–2020)
Semantic web — machines understand and personalize data.
Web 4.0 (2020–2030)
Intelligent, AI-driven, decentralized "web OS".

Internet vs. World Wide Web

The InternetThe World Wide Web
LayerHardware / network layerApplication / data layer
What it isA globally decentralized network of networks running TCP/IP — routers, fiber, packet switching, IP routingAn information system running on top of the Internet, using hypertext, URIs and HTTP

Key takeaway: the Internet provides the infrastructure (the roads); the WWW provides the service (the traffic on them).

Browsers, Servers & the Client–Server Model

The Web runs on a client–server architecture: the browser requests a resource and the server returns it. A browser is a software interface — Chrome, Opera Mini, Internet Explorer — that renders text/pictures/animation/video, and also handles searching, file transfer and mail.

Web browser
Rendering engine (Blink, Gecko, WebKit) builds the DOM/CSSOM; a JS engine (V8, SpiderMonkey) runs scripts; a network/storage layer handles cache, cookies and TLS.
Web server
Listens on ports 80/443, serves files or routes to an app. Apache uses one process/thread per connection; Nginx/Node.js is async event-driven, handling 10k+ connections efficiently.

HTTP: Request & Response

Request
Line: method + URI + version, e.g. GET /api/data HTTP/1.1 · Headers: Host, User-Agent, Accept · Body: payload for POST/PUT
Response
Status line: version + code, e.g. HTTP/1.1 200 OK · Headers: Content-Type, Set-Cookie, Cache-Control · Body: HTML, CSS or JSON

Request–response lifecycle:

  1. DNS resolution — browser converts the domain to an IP via local cache → recursive resolver → root/TLD → authoritative DNS.
  2. TCP 3-way handshake — client sends SYN, server replies SYN-ACK, client sends ACK, on port 80 or 443.
  3. HTTP transmission — client sends the request; server runs routing/DB logic and returns the response.
  4. Teardown / keep-alive — socket closes, or stays open for further requests.

URI vs. URL

URI is the umbrella term for anything that identifies a resource — a URL identifies by location, a URN identifies by name regardless of location (e.g. urn:isbn:978-0-395-36341-6). A URL is a URI that also tells you how to reach the resource, so it always includes a scheme, e.g. https://www.google.com. Analogy: a URI is like a person's name; a URL is their full home address.

Domain Names, Labels & TLDs

Domain names are human-readable stand-ins for hard-to-remember IP addresses, and are parsed right to left (e.g. developer.mozilla.org → TLD → label1 → label2). A label can be 1–63 characters, is case-insensitive, and may only use letters, digits and hyphens (never as the first/last character). The label directly before the TLD is the second-level domain (SLD); a domain isn't limited to 3 labels — informatics.ed.ac.uk is valid, and any base domain can delegate subdomains (support.mozilla.org).

Generic TLDs
.com, .org, .net — no eligibility rules.
Country-code TLDs
.in, .fr, .us — may require local language or hosting.
Restricted TLDs
.gov (government only), .edu / .ac (accredited institutions only).

You never permanently own a domain — you pay a registrar (which uses a registry) for the right to use it for one or more years, renewable ahead of other applicants. Some TLDs skip standard registrars entirely — every .fire domain, for example, is managed directly by Amazon.

An IP address is a unique numeric label assigned to every network-connected device, allocated under IANA rules (ranging 0.0.0.0–255.255.255.255 for IPv4).

IPv4 Limitations, IPv6 Benefits & Address Classes

IPv4's 32-bit space is nearly exhausted, and it shows in three places: scalability (limited addresses plus wasteful broadcast overhead), routing (complex, variable-length headers and manual/DHCP misconfiguration slow every hop), and security (IPsec isn't built in, and QoS prioritisation for real-time video/voice is weak). IPv6 fixes all three with a 128-bit space, a simplified fixed 40-byte header, built-in IPsec, native QoS, and mobile-friendly design.

Transition strategies: dual stacking (a device runs IPv4 and IPv6 side by side), tunneling (IPv6 packets are wrapped inside IPv4 to cross older networks), and NAT (translates addresses so the two IP versions can talk to each other).

IP vs. MAC Address, and Staying Safe

IP address
Network-layer connection identifier, 4 bytes (IPv4) or 16 bytes (IPv6), assigned by the ISP, usually dynamic, and visible to third parties online.
MAC address
Data-link-layer physical identifier, 6-byte hex, set by the hardware manufacturer, static/permanent, and private — visible only on your own LAN.

An exposed IP can be used for geographic tracking, targeted DDoS attacks, or to falsely implicate you in illegal downloads. Protect it with a VPN, a proxy server, a NAT firewall, ISP-rotated dynamic IPs, or simply by resetting your modem.

Dynamic IP & Dynamic DNS (DDNS)

Problem: standard DNS A-records map a domain to a fixed IP. When a home or small-business server's dynamic IP changes, the domain lookup breaks.

Solution: a lightweight DDNS daemon on the server watches the WAN IP; whenever it changes, the daemon sends an authenticated API request that updates the DNS A-record within seconds, keeping the domain reliably pointed at the server.

Web 2.0 Technologies

AJAX / async
XMLHttpRequest and fetch() fetch data in the background without a full reload — enabling single-page apps.
User-generated content
Shift from static one-way pages to participatory platforms — social networks, wikis, blogs.
RESTful APIs
Lightweight JSON over HTTP REST replaced heavy SOAP/XML, enabling third-party mashups.
SaaS
Apps moved from installed binaries to cloud-hosted browser apps (Docs, Figma, Office 365).

Deploying a Linux Web Server

  1. Install packages — sudo apt update && sudo apt install apache2 nginx on Debian/Ubuntu.
  2. Directory & permissions — document root at /var/www/html, ownership assigned via chown.
  3. Virtual hosts — per-domain config files in sites-available, letting one IP serve multiple domains.
  4. Firewall & SSL — open HTTP/HTTPS ports with ufw; issue certificates via Let's Encrypt / Certbot.

Effective Web Design Principles

Visual hierarchy / F-pattern
Users scan, not read — eye-tracking shows an F-shaped pattern, so put logos, nav and CTAs along the top-left path.
3-click rule
Clear sitemaps and breadcrumbs so any content is reachable within 3 clicks.
Responsive design (RWD)
Fluid layouts across phones/tablets/desktops via media queries, flexbox and grid.
Accessibility (WCAG 2.1)
Minimum 4.5:1 text contrast, image alt text, full keyboard navigation.
Performance
Core Web Vitals (LCP/CLS/FID) improved via image compression, minification, CDNs; 1s loads convert far better than 4s loads.
Cross-browser & security
CSS resets/autoprefixer for engine differences; enforce Content-Security-Policy headers to block XSS and clickjacking.
