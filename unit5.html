XML: Structure, Validation, and Transformation

Learn how XML represents structured information, how DTD and XML Schema describe valid documents, and how XPath and XSLT select and transform data.

01. Introduction to XML

XML (Extensible Markup Language) is a text-based format for representing, storing and transporting structured data. Unlike HTML, which has predefined elements with browser-defined meaning, XML lets authors choose descriptive names that fit their information. XML describes what data means; another program or stylesheet decides how to process or display it.

XML
<course code="WT205">
    <title>Web Technologies</title>
    <credits>4</credits>
    <instructor>Dr. Mehta</instructor>
</course>
Extensible

Authors choose meaningful element and attribute names for their domain; XML does not prescribe one fixed vocabulary.

Structured

Elements nest in a tree, so records can contain related child records in a clear parent–child relationship.

Portable text

XML is readable text that software can process across platforms. It is a data format, not a programming language.

XML is not HTML: XML focuses on carrying data and does not automatically create a styled user interface. It is commonly used to exchange information between applications, store configuration and documents, and represent feeds such as RSS.

Well-formed versus valid

A well-formed document follows XML syntax rules, including a single root, correctly nested and closed elements, and quoted attribute values. A valid document is well-formed and also conforms to a declared grammar, such as a DTD or XML Schema (XSD). A browser parser can check basic well-formedness, but does not automatically validate against every DTD or XSD.

02. XML Key Components

An XML document is a tree of nodes. This example includes a declaration, a root element, nested elements, attributes, text and a comment.

XML
<?xml version="1.0" encoding="UTF-8"?>
<student id="s-204" status="active">
    <name>Mira Shah</name>
    <programme>B.Tech CSE</programme>
    <marks subject="XML">88</marks>
    <!-- A student record -->
</student>

03. XML Syntax and Well-Formedness

  • Element names are case-sensitive: <Name> and <name> are different names.
  • Every opened element must be closed, or use empty-element syntax such as <image/>.
  • Elements must be properly nested. <b><i>...</b></i> is not well-formed.
  • There must be exactly one document element (root), though it may have many children.
  • Attribute values must be quoted, for example id="s-204".
  • Escape reserved characters in text: use &amp;, &lt; and &gt; for ampersand, less-than and greater-than.

Remember: well-formedness is the baseline syntax requirement. Validation against a DTD or XSD adds application-specific rules such as required elements, order, occurrence counts and data types.

04. XML Namespaces

Namespaces prevent naming collisions when XML from different vocabularies is combined. An xmlns declaration connects a prefix to a namespace URI. The URI identifies the vocabulary; it does not have to be a working web page.

XML
<course xmlns:lib="https://example.edu/library">
    <title>Web Technologies</title>
    <lib:title>XML for Libraries</lib:title>
</course>

The unprefixed title and prefixed lib:title are distinct names because the latter belongs to the library namespace.

05. DTD and XML Schema

Well-formedness checks syntax, but does not specify which elements an application expects. A grammar defines allowed elements and attributes, their order, and how often they may appear. XML processors can use a grammar to validate a document before an application consumes it.

DTD (Document Type Definition)

A compact grammar declaring elements, attributes, entities and content models. A DTD can be embedded in the XML document or saved as an external .dtd file. Its syntax is not itself XML, and its data typing is limited.

XML Schema (XSD)

An XML-based grammar with built-in types such as xs:decimal, constraints, namespaces and reusable type definitions. XSD is more expressive and strongly typed than DTD.

Describe a catalog with a DTD

This DTD requires one or more product elements, each containing name followed by price; every product must have an id attribute.

DTD · catalog.dtd
<!ELEMENT catalog (product+)>
<!ELEMENT product (name, price)>
<!ATTLIST product id ID #REQUIRED>
<!ELEMENT name (#PCDATA)>
<!ELEMENT price (#PCDATA)>

Connect an instance to the external DTD with a document type declaration:

XML · catalog.xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE catalog SYSTEM "catalog.dtd">
<catalog>
    <product id="p101">
        <name>Notebook</name>
        <price>45.50</price>
    </product>
</catalog>

Describe the same structure with XSD

XML Schema · catalog.xsd
<?xml version="1.0" encoding="UTF-8"?>
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
    <xs:element name="catalog">
        <xs:complexType>
            <xs:sequence>
                <xs:element name="product" maxOccurs="unbounded">
                    <xs:complexType>
                        <xs:sequence>
                            <xs:element name="name" type="xs:string"/>
                            <xs:element name="price" type="xs:decimal"/>
                        </xs:sequence>
                        <xs:attribute name="id" type="xs:ID" use="required"/>
                    </xs:complexType>
                </xs:element>
            </xs:sequence>
        </xs:complexType>
    </xs:element>
</xs:schema>

For XSD validation, declare the schema in the XML root instead of using the DTD declaration:

XML
<catalog xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:noNamespaceSchemaLocation="catalog.xsd">
    ...
</catalog>

06. Validating XML Documents

Save the DTD-backed document as catalog.xml beside catalog.dtd, then validate it with xmllint --noout --valid catalog.xml. For an XSD-backed document, replace the DTD declaration with the schema header and run xmllint --noout --schema catalog.xsd catalog.xml. These commands use the xmllint utility from libxml2; successful validation reports that the document validates.

A browser's DOMParser can report malformed XML, but that is not the same as checking a document against a DTD or XSD. Use a validator that supports the grammar when schema validation is required.

07. Transforming XML with XSL and XSLT

XSL (Extensible Stylesheet Language) is a family of XML technologies. Its key parts include XSLT (transformation rules), XPath (expressions for selecting nodes and values), and XSL-FO (formatting objects often used for paginated output). Introductory materials sometimes use “XSL” informally to mean an XSLT stylesheet.

XSLT reads a source XML tree, selects nodes with XPath, and applies template rules to produce HTML, another XML vocabulary or plain text. It changes the representation of data, not the source XML.

XSLT 1.0
<xsl:stylesheet version="1.0"
    xmlns:xsl="http://www.w3.org/1999/XSL/Transform">
    <xsl:output method="html" indent="yes"/>
    <xsl:template match="/">
        <table>
            <tr><th>ID</th><th>Title</th><th>Author</th><th>Price (INR)</th></tr>
            <xsl:for-each select="catalog/book">
                <tr>
                    <td><xsl:value-of select="@id"/></td>
                    <td><xsl:value-of select="title"/></td>
                    <td><xsl:value-of select="author"/></td>
                    <td><xsl:value-of select="price"/></td>
                </tr>
            </xsl:for-each>
        </table>
    </xsl:template>
</xsl:stylesheet>
  • <xsl:template match="/"> starts at the document root.
  • <xsl:for-each select="catalog/book"> selects each book with XPath and repeats the enclosed output.
  • <xsl:value-of select="@id"/> reads an attribute; selecting title or author reads an element's text.
  • Literal HTML elements such as <table> become part of the result document.

Connect an XML file to a stylesheet

A standalone XML file can associate with an XSLT file using an xml-stylesheet processing instruction. Save the XML and stylesheet together, then open the XML in a browser that supports the instruction.

XML
<?xml version="1.0" encoding="UTF-8"?>
<?xml-stylesheet type="text/xsl" href="catalog.xsl"?>
<catalog>
    <book id="b101">
        <title>Learning XML</title>
        <author>Asha Rao</author>
        <price>450</price>
    </book>
</catalog>

For a command-line demonstration, save the stylesheet as catalog.xsl and run xsltproc catalog.xsl catalog.xml. The transformed HTML is written to standard output; xsltproc is available with libxslt.

Compatibility: the interactive example below uses XSLT 1.0 through the browser's XSLTProcessor API. Chromium warns that browser XSLT support is deprecated and may be removed; use xsltproc for a durable local demonstration. Browser support is not a substitute for server-side validation.

Unit 5 Recap

  1. XML is an extensible, text-based format for structured data.
  2. Elements, attributes, text and namespaces make up the document tree; well-formedness is the baseline syntax requirement.
  3. DTD and XSD declare allowed document structure. XSD adds richer types and constraints.
  4. XSLT uses XPath and template rules to transform XML into HTML, XML or text.
